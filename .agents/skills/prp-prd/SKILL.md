# PRP requirements

Use the requested idea, or start with the problem and target user. Work through short discovery rounds. Reflect decisions back to the user and ask the next useful question before freezing disputed scope.

1. Discover the problem, frequency and severity, users, existing workarounds, and why the work matters now. Label evidence, hypotheses, and unknowns.
2. Ground the proposal in current product or market evidence when relevant. Cite sources and record open research questions. Inspect the project's stack, patterns, dependencies, and integration limits. Check feasibility and major risks before selecting scope.
3. Agree on the hypothesis, primary user journey, scope and exclusions, measurable success, and MoSCoW priorities. Contrast proposed delivery options only when an actual decision is open.
4. Save `docs/PRPs/prds/<name>.prd.md` with Problem, Evidence, Proposed Solution, Hypothesis, Exclusions, Success Metrics, Open Questions, Users and Context, Capabilities and MVP, User Flow, Technical Approach, Implementation Phases, Decisions, and Research. In the phase table record order, objective, validation, dependencies, parallelism, status (`pending` initially), and plan link.
5. Report the artifact, validation status, open questions, and next phase. Hand off to [prp-plan](../prp-plan/SKILL.md) on request.
